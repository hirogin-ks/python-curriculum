# 第1回：スクレイピング入門

## 今回のゴール

- スクレイピングが何かわかる
- やっていいこと・ダメなことがわかる
- robots.txt が読める

## 1.1 導入：こんな経験はありませんか？

毎日、複数のニュースサイトを巡回して、特定のジャンルの記事だけをピックアップしてまとめる作業を任されたとします。1日ならまだしも、これを毎日続けるのは大変です。

あるいは、複数のECサイトで同じ商品の価格を比較したいとき、1つ1つのサイトを開いて価格を確認し、Excelに転記する作業を想像してください。10商品ならまだしも、100商品となると気が遠くなります。

このような「Webサイトから情報を集めて整理する」という作業は、人間がやると時間がかかり、ミスも起きやすいものです。

**しかし、プログラミングの「スクレイピング」という技術を使えば、この作業を自動化できます。**

一度プログラムを書いてしまえば、あとはボタン1つで何百ものページから情報を集め、整理してくれます。これがスクレイピングの力です。

## 1.2 ハンズオン：実際のrobots.txtを見てみよう

スクレイピングを学ぶ前に、まず「ルール」を知る必要があります。Webサイトには、スクレイピングをしていい場所とダメな場所が決められていることがあります。それを記載しているのが「robots.txt」というファイルです。

### 手順

1. ブラウザを開く
2. アドレスバーに以下のURLを入力してEnterを押す

```url
https://www.google.com/robots.txt
```

3. 表示された内容を眺めてみる

どうでしょうか。何やら英語で色々と書かれていると思います。`User-agent` や `Disallow` といった単語が見えるはずです。

次に、別のサイトも見てみましょう。

```url
https://github.com/robots.txt
```

サイトによって、書かれている内容が異なることが分かります。この「robots.txt」の読み方を、この回で学びます。

## 解説

### スクレイピングとは何か

**Webスクレイピング**とは、Webサイトからデータを自動で収集する技術のことです。

普段、私たちがブラウザでWebサイトを見るとき、裏側では以下のようなやり取りが行われています。

```text
ブラウザ                    Webサーバー
   │                           │
   │── 「このページをください」──▶│
   │                           │
   │◀── 「HTMLをどうぞ」────────│
   │                           │
   ↓
ブラウザがHTMLを解釈して
画面に表示する
```

スクレイピングでは、この「ブラウザ」の役割をプログラムが担います。プログラムがWebサーバーに対してページを要求し、返ってきたHTMLを解析して、必要なデータだけを取り出します。

**HTML**とは、Webページの構造を記述するための言語です。ブラウザはHTMLを読み取って、私たちが見ている画面を表示しています。

### 身近な例

スクレイピングは、実は身近なサービスでも使われています。

| サービス | 何をしているか |
|---------|---------------|
| 価格比較サイト | 複数のECサイトから商品価格を自動収集 |
| ニュースアプリ | 複数のニュースサイトから記事を自動収集 |
| 求人まとめサイト | 複数の求人サイトから求人情報を自動収集 |
| 不動産情報サイト | 複数の不動産サイトから物件情報を自動収集 |

---

## やっていいこと・ダメなこと

スクレイピングは便利な技術ですが、使い方を間違えると法律に違反したり、他者に迷惑をかけたりする可能性があります。必ずルールを守って利用してください。

### やってはいけないこと

| 行為 | 理由 |
|-----|------|
| 短時間に大量のアクセスを行う | サーバーに過剰な負荷がかかり、サービスが停止する原因になる。業務妨害として訴えられる可能性がある |
| ログインが必要なページに不正にアクセスする | 不正アクセス禁止法に違反する |
| 収集したデータを無断で公開・販売する | 著作権法に違反する可能性がある |
| 利用規約でスクレイピングを禁止しているサイトで実行する | 利用規約違反となり、法的措置を取られる可能性がある |

### やっていいこと

| 行為 | ポイント |
|-----|---------|
| robots.txt で許可されている範囲でアクセスする | サイトが定めたルールに従っている |
| アクセス間隔を1〜3秒以上空ける | サーバーに優しい |
| 個人的な分析や研究目的で使用する | 商用利用や公開をしなければ問題になりにくい |
| 公式APIが提供されている場合はそちらを使う | サイトが正式に用意した窓口であり、最も安全 |

### 実際に問題になった事例

スクレイピングに関連して、実際に法的問題になった事例があります。

- 2010年：岡崎市立中央図書館の蔵書検索システムに対して、1秒に1回程度のアクセスを行ったプログラマーが逮捕された（後に不起訴）
- 2017年：チケット転売サイトが、公式チケット販売サイトに対して大量のアクセスを行い、業務妨害で摘発された

これらの事例から分かるように、たとえ悪意がなくても、サーバーに負荷をかける行為は問題視される可能性があります。

## robots.txt の読み方

### robots.txt とは

robots.txt は、Webサイトの管理者が「どのページにアクセスしてよいか」を示すためのファイルです。検索エンジンのクローラー（Webページを自動で巡回するプログラム）や、スクレイピングプログラムに対して、アクセスのルールを伝える役割があります。

### 場所

robots.txt は、サイトのルートディレクトリに置かれています。つまり、サイトのURLの末尾に `/robots.txt` を付けるとアクセスできます。

```url
https://example.com/robots.txt
```

### 基本的な構文

```text
User-agent: *
Disallow: /admin/
Disallow: /private/
Crawl-delay: 5
```

| 項目 | 意味 |
|-----|------|
| User-agent | 対象となるクローラーを指定する。`*` は「すべてのクローラー」を意味する |
| Disallow | アクセスを禁止するパスを指定する |
| Allow | アクセスを許可するパスを指定する（Disallowの例外を設ける場合に使用） |
| Crawl-delay | アクセス間隔を秒数で指定する |

### よくあるパターン

#### パターン1：すべて許可

```bash
User-agent: *
Disallow:
```

Disallowの後に何も書かれていない場合、禁止されているパスがないことを意味します。つまり、すべてのページにアクセス可能です。

#### パターン2：すべて禁止

```bash
User-agent: *
Disallow: /
```

`/` はサイト全体を意味します。つまり、すべてのページへのアクセスが禁止されています。

#### パターン3：特定のディレクトリのみ禁止

```bash
User-agent: *
Disallow: /admin/
Disallow: /private/
```

`/admin/` と `/private/` 配下のページへのアクセスが禁止されています。それ以外のページにはアクセス可能です。

#### パターン4：特定のクローラーに対する指定

```bash
User-agent: Googlebot
Allow: /

User-agent: *
Disallow: /
```

Googleのクローラー（Googlebot）にはすべてのページへのアクセスを許可し、それ以外のクローラーにはすべてのページへのアクセスを禁止しています。

自分で作成したスクレイピングプログラムは「Googlebot」ではないので、`User-agent: *` のルールが適用されます。

## 練習問題

### 1.3 問題1：robots.txt を読んでみよう

以下の robots.txt を見て、質問に答えてください。

```bash
User-agent: Googlebot
Allow: /

User-agent: *
Disallow: /admin/
Disallow: /api/
Crawl-delay: 3
```

**Q1.** 自分で作ったプログラムで `/public/page.html` にアクセスしていいか？

**Q2.** 自分で作ったプログラムで `/admin/users.html` にアクセスしていいか？

**Q3.** アクセスする際、何秒間隔を空けるべきか？

---

### 考え方のヒント

**Q1の考え方:**

1. 自分のプログラムは「Googlebot」ではないので、`User-agent: *` のルールを見る
2. `Disallow` には `/admin/` と `/api/` が指定されている
3. `/public/page.html` はどちらにも該当しない
4. 該当しないということは、アクセスが許可されている

**Q2の考え方:**

1. `User-agent: *` のルールを見る
2. `Disallow: /admin/` と書いてある
3. `/admin/users.html` は `/admin/` 配下のパスである
4. つまり、アクセスが禁止されている

### 1.5 問題3：この場合はどうする？

以下のシナリオについて、スクレイピングを行ってよいかどうか考えてください。

**シナリオA:**

毎日1回、ニュースサイトの見出しを収集して、個人的なメモとして保存したい。robots.txt には特に禁止事項が書かれていない。

**シナリオB:**

SNSから有名人の投稿を収集して、自分のブログに全文を転載したい。

**シナリオC:**

ECサイトから商品価格を1時間に1回収集して、価格変動をグラフ化したい。robots.txt では該当ページへのアクセスは許可されている。

---

### 考え方のヒント

**シナリオA:**

- robots.txt で許可されている
- アクセス頻度が「毎日1回」であり、サーバーへの負荷は最小限
- 収集するのは「見出し」のみであり、記事全文ではない
- 個人的な使用であり、公開しない

これらの条件から、一般的には問題ないと考えられます。ただし、サイトの利用規約も確認することをお勧めします。

**シナリオB:**

- SNSの多くは利用規約でスクレイピングを禁止している
- 投稿の「全文転載」は著作権法に違反する可能性が高い
- たとえ技術的に可能でも、やってはいけない

**シナリオC:**

- robots.txt で許可されている
- 1時間に1回というアクセス頻度は妥当
- 価格情報を個人的に分析する目的であれば問題ない

ただし、収集したデータを商用目的で使用したり、公開したりする場合は別途確認が必要です。
